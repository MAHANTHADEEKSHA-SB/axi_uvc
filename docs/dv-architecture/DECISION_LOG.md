## Proposed under D-001, not yet confirmed by the owner

Each changes an accepted AXI decision (NN-05), so each needs the owner's confirmation; the reason is the APB/AHB architecture the owner asked to follow. Until confirmed they are implemented proposals, like the protocol defaults below.

| ID | Changes | Proposal | Reason |
|---|---|---|---|
| S-1 | A-10 | Four packages instead of one: `axi_bfm_pkg` (HDL types, no UVM), `axi_api_pkg`, `axi_uvc_pkg`, `axi_adapter_pkg`, in the FILE-07 order | The width-specialized adapters name BFM interface types and must follow the HDL; the non-parameterized core must compile without them (ADR-001 decision 3); HDL code cannot import a UVM package |
| S-2 | A-11 | The APB/AHB layout under `poc/axi_uvc/` (`DIRECTORY_ARCHITECTURE.md`); the empty placeholders of PR #14 removed | One layout, filelists, scripts and docs set across the three repositories; "create paths as files are implemented, not empty placeholders" |
| S-3 | A-8, A-9 | No UVM `drive_transfer`/`collect_transfer`/`check_transfer` hooks and no `axi_base_driver`/`axi_base_monitor`: pin behaviour is in the HDL BFMs behind proxies — `drive_transfer` → `axi_drive_proxy_base::send()` / `axi_respond_proxy_base::send_response()`, `collect_transfer` → `axi_monitor_proxy_base::receive()`, `check_transfer` → the monitor BFM's counted checks reported by `axi_monitor::check_phase` | ADR-001/002: UVM classes never touch pins or virtual interfaces; with the hooks gone the driver/monitor base classes would hold no shared skeleton |
| S-4 | A-5 | Per-agent protocol checking by each agent's monitor BFM instead of `axi_m/s_protocol_checker` classes; `src/env/axi_env.sv` and `axi_system_checker.sv` become test code (`tests/axi_poc_env.sv`, `tests/axi_poc_scoreboard.sv`) | Cycle rules need cycle sampling (HDL); `ARCHITECTURE_CONTRACT.md`: no environment framework in the core; the cross-agent check needs both roles on one bus, which is a test topology |
| S-5 | A-6 | `axi_cfg` → `axi_agent_cfg`; `protocol_mode` → `features.protocol` (the `AXI4_FULL`/`AXI4_LITE` names kept); widths are the bound adapters' parameters, cross-checked (CFG-06), not cfg fields | APB/AHB naming; ADR-001: widths are HDL parameters, so a cfg field could disagree with the bus |
| S-6 | names | `axi_m_*`/`axi_s_*` (master/slave) → `axi_mgr_*`/`axi_sub_*` (Manager/Subordinate); `axi_base_transaction` → `axi_transaction` | IHI 0022 terminology since Issue H.b; NAME-12 avoids single-letter names; APB/AHB naming |
